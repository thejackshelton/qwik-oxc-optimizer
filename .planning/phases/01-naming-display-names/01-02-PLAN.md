Fix default export naming to match SWC's `fold_export_default_expr` behavior:

SWC logic (from research):
```rust
fn fold_export_default_expr(&mut self, node: ast::ExportDefaultExpr) -> ast::ExportDefaultExpr {
    let mut filename = self.options.path_data.file_stem.clone();
    if filename == "index" {
        if let Some(foldername) = self.options.path_data.rel_dir.file_name().and_then(|s| s.to_str()) {
            filename = foldername.to_string();
        }
    }
    self.stack_ctxt.push(filename);
    let o = node.fold_children_with(self);
    self.stack_ctxt.pop();
    o
}
```

Implement `enter_export_default_declaration` / `exit_export_default_declaration` (or the appropriate OXC traverse callback for default exports):
1. Compute `file_stem` from `self.filename` (strip extension: "test.tsx" -> "test")
2. If `file_stem == "index"`, attempt to use the folder name from the file path. The `self.filename` may be just "test.tsx" (no directory info). Check if `self.options` has a `path` or `rel_dir` field. If not, fall back to "index" itself.
3. Push `file_stem` (or folder name) to `stack_ctxt`
4. Pop in exit callback

This replaces OXC's current behavior of using the literal "default" as the display name for default exports.

2. Hashes: `scope? + rel_path + full_display_name` where `full_display_name = "{file_name}_{display_name}"`
3. The file_name prefix is added to display_name AFTER dedup but BEFORE hashing

OXC's current `compute_segment_hash` receives `(scope, rel_path, display_name)`. Verify that:
- `rel_path` is `self.filename` (e.g., "test.tsx")
- `display_name` is the FULL display name with filename prefix (e.g., "test.tsx_renderHeader_component")
