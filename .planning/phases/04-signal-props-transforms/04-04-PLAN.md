This task has three interconnected changes that must be implemented together:

**Part A: Extend `analyze_props_destructuring` to detect non-destructured `(props)` params with body destructuring**

In `props_destructuring.rs`, modify `analyze_props_destructuring` to detect `BindingIdentifier` (non-destructured) first parameters. Currently, when the first param is a `BindingIdentifier` like `props`, it returns `needs_transform = false` immediately.

New behavior: When the first param is a `BindingIdentifier`:
1. Store the identifier name (e.g., `"props"`) as `raw_props_name` on the info struct.
2. Add a new field `props_param_name: Option<String>` to `PropsDestructuringInfo`. Set it to `Some("props")` when the first param is a plain identifier. This tells downstream code the props param name for signal wrapping.
3. Do NOT set `needs_transform = true` yet -- we need to check for body destructuring first.

Create a new public function `detect_body_destructuring(statements: &[Statement], props_param_name: &str) -> Option<BodyDestructuringInfo>` that scans the arrow body for statements of the form:
```
const { "key1": alias1, key2, ...rest } = <props_param_name>;
```

Specifically, match `Statement::VariableDeclaration` where:
- The declaration has exactly one declarator
- The declarator's `init` is an `Expression::Identifier` matching `props_param_name`
- The declarator's pattern is a `BindingPattern::ObjectPattern`

Extract the same info as `analyze_props_destructuring` does for ObjectPattern parameters (prop_keys, rest_name, prop_defaults), plus store the statement's index for removal.

Return a `BodyDestructuringInfo` struct:
```rust
pub(crate) struct BodyDestructuringInfo {
    pub prop_keys: Vec<(String, String)>,  // (original_key, local_alias)
    pub rest_name: Option<String>,
    pub prop_defaults: HashMap<String, String>,
    pub stmt_index: usize,  // index of the destructuring statement to remove
}
```

**Part B: Wire body destructuring detection into `transform.rs`**

In `transform.rs`, in the `enter_call_expression` handler for `component$` (around line 1303):

After calling `analyze_props_destructuring`, if `info.needs_transform` is false BUT the first param is a `BindingIdentifier`:
1. Extract the props param name from the arrow's first parameter.
2. Set `info.props_param_name = Some(param_name.clone())`.
3. Set `info.raw_props_name = param_name.clone()` (the prop parameter keeps its name, unlike destructured case which uses `_rawProps`).
4. Set `self.active_props_info = Some(info)` even though `needs_transform` is false -- we need the info for `detect_signal_wrap`.

In the `exit_expression` handler for component$ (around line 1859):

When `props_info` is Some and `props_info.props_param_name` is Some (i.e., non-destructured props):
1. Call `detect_body_destructuring` on the arrow body statements.
2. If body destructuring is found:
   a. Do NOT replace the parameter (keep `(props)` as-is -- unlike the destructured case which changes to `(_rawProps)`)
   b. Remove the destructuring statement at `stmt_index`
   c. If rest_name exists: insert `const rest = _restProps(props, ["key1", "key2"])` at the position where the removed statement was
   d. Rewrite remaining body statements: replace each local alias identifier with `_wrapProp(props, "originalKey")` in JSX contexts, or `props["originalKey"]` in non-JSX contexts (like `useSignal(props["bind:value"])`)
   e. Update the segment's param_names to `["props"]` (the actual param name)
3. If no body destructuring is found: still store `props_param_name` for Part C.

IMPORTANT: Look at the SWC golden snapshots to determine the EXACT rewrite behavior:

For `destructure_args_colon_props`:
- Input: `const { "bind:value": bindValue } = props; return <>{bindValue}</>;`
- Output: parameter stays `(props)`, destructuring removed, `bindValue` in JSX children becomes `_wrapProp(props, "bind:value")`
- Note: `_wrapProp` import is added

For `destructure_args_colon_props2`:
- Input: `const { "bind:value": bindValue } = props; const test = useSignal(bindValue); return <>{test.value}</>;`
- Output: parameter stays `(props)`, destructuring removed, `useSignal(bindValue)` becomes `useSignal(props["bind:value"])` (NOT _wrapProp!), `test.value` becomes `_wrapProp(test)` (1-arg form)
- Key insight: body destructuring aliases in NON-JSX positions are rewritten to `props["key"]` member access, NOT `_wrapProp`

For `destructure_args_colon_props3`:
- Input: `const { test, ...rest } = props; const test = useSignal(rest["bind:value"]); return <>{test.value}</>;`
- Output: `const rest = _restProps(props, ["test"]);`, then `useSignal(rest["bind:value"]);`, then `_fnSignal(_hf0, [props], _hf0_str)` where `_hf0 = (p0) => p0.test.value`
- Key insight: When there's a rest pattern, `_restProps(props, [...])` is used with the ORIGINAL props param name, not `_rawProps`

**Part B edge case 4: `prop_origin_map` for destructured-from-props variables (required for `destructure_args_colon_props3`)**

The `destructure_args_colon_props3` test requires three specific algorithms not covered by the general body destructuring logic above:

1. **Statement stripping**: The `const test = useSignal(rest["bind:value"])` statement has its `const test =` binding stripped, leaving only `useSignal(rest["bind:value"])` as an expression statement. This happens because `test` was originally a destructured prop key (from `const { test, ...rest } = props`). When body destructuring is detected, any subsequent `const <alias> = <expr>` where `<alias>` matches a non-rest prop key from the destructuring must be converted from a `VariableDeclaration` to an `ExpressionStatement` containing just the `<expr>` part. Algorithm:
   - After parsing `BodyDestructuringInfo`, collect the set of non-rest prop local aliases (e.g., `{"test"}` from `{ test, ...rest }`).
   - Walk subsequent body statements looking for `const <name> = <init_expr>` where `<name>` is in that set.
   - Replace the `VariableDeclaration` statement with an `ExpressionStatement` containing just `<init_expr>`.

2. **`prop_origin_map` construction**: Build a `HashMap<String, String>` mapping each non-rest destructured local alias back to its prop path relative to the props param. For `const { test, ...rest } = props`, this produces `{ "test" => "props.test" }` (i.e., local name `test` originated from `props.test`). Store this map on the transform context or pass it alongside `props_param_name`.

3. **`collect_reactive_deps` substitution using `prop_origin_map`**: When `collect_reactive_deps` encounters `test.value` (a `StaticMemberExpression` where the object is an identifier in `prop_origin_map`):
   - Instead of treating `test` as the dep (which would produce `[test]` and `(p0) => p0.value`), substitute the dep as `props` (the props param identifier from the map entry `props.test`).
   - Build the hoisted function parameter access as `p0.test.value` instead of the normal `p0.value`. That is, prepend the prop key path between `p0` and `.value`.
   - This produces: deps array `[props]` and hoisted function `(p0) => p0.test.value`, which is the SWC-expected output `_fnSignal(_hf0, [props], _hf0_str)` where `_hf0 = (p0) => p0.test.value`.
   - Implementation: In `collect_reactive_deps_inner`, when the expression is `<ident>.value` and `<ident>` is found in `prop_origin_map` as `<props_name>.<key>`, return the dep as `<props_name>` (the props param) and store the key chain `[<key>, "value"]` for building the hoisted function body. The hoisted function builder must then construct `p0.<key>.value` instead of the usual `p0.value`.

**Part C: Extend `detect_signal_wrap` to handle `props.X` and `props["X"]` patterns**

In `jsx_transform.rs`, modify `detect_signal_wrap` to accept an additional parameter: `props_param_name: Option<&str>`.

Add new match arms:

1. In the existing `Expression::StaticMemberExpression` branch, after checking for `_rawProps`:
   ```rust
   // Non-destructured props param: props.class -> _wrapProp(props, "class")
   if let Some(param_name) = props_param_name {
       if let Expression::Identifier(ident) = &member.object {
           if ident.name.as_str() == param_name && prop_name != "value" {
               return SignalWrapResult::WrapPropNamed(prop_name.to_string());
           }
       }
   }
   ```

2. Add a new `Expression::ComputedMemberExpression` arm:
   ```rust
   Expression::ComputedMemberExpression(member) => {
       if let Some(param_name) = props_param_name {
           if let Expression::Identifier(ident) = &member.object {
               if ident.name.as_str() == param_name {
                   // props["bind:value"] -> _wrapProp(props, "bind:value")
                   if let Expression::StringLiteral(s) = &member.expression {
                       return SignalWrapResult::WrapPropNamed(s.value.to_string());
                   }
               }
           }
       }
       SignalWrapResult::None
   }
   ```

When building the `_wrapProp` call for `WrapPropNamed` on a non-`_rawProps` source, the source object must be the props param identifier (e.g., `props`), not `_rawProps`. The `WrapPropNamed` source extraction must be updated at BOTH call sites:

1. **Attribute handler** (jsx_transform.rs, ~line 1127): The existing code handles `StaticMemberExpression` by extracting `member.unbox().object`. Add a second arm for `ComputedMemberExpression`: `if let Expression::ComputedMemberExpression(member) = value { member.unbox().object }`. The `else` fallback (line ~1132) builds `_rawProps` which is only correct for destructured prop identifiers; `ComputedMemberExpression` (e.g., `props["bind:value"]`) must NOT fall through to this else branch.

2. **Children handler** (jsx_transform.rs, ~line 1614): Same pattern -- the existing code handles `StaticMemberExpression`. Add the same `ComputedMemberExpression` arm: `if let Expression::ComputedMemberExpression(member) = other { member.unbox().object }`. Without this, `props["class"]` in children would incorrectly use `_rawProps` as the source.

Both sites must match this combined pattern:
```rust
let source_obj = if let Expression::StaticMemberExpression(member) = expr {
    member.unbox().object
} else if let Expression::ComputedMemberExpression(member) = expr {
    member.unbox().object
} else {
    // Fallback for destructured prop identifiers only
    ctx.ast.expression_identifier(SPAN, "_rawProps")
};
```

For `collect_reactive_deps`, extend it to recognize the props param name as a reactive source (like `_rawProps` currently is). When `props.X` or `props["X"]` is encountered and `props` is the component props param, treat it as a primary reactive dep just like `_rawProps.X`.
