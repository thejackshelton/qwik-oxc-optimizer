<objective>
Fix JSX immutability flag propagation so parent elements correctly detect mutable subtrees.

Purpose: Close the ~68 flag mismatches where OXC produces flag=3 (fully static) while SWC produces flag=1 (static_listeners only). Two complementary root causes:

1. **Already-transformed children in expression containers**: When a non-immutable component like `<Stuff/>` is nested inside a ternary or logical expression like `{cond ? <p/> : <Stuff/>}`, OXC's bottom-up traversal transforms `<Stuff/>` first via `exit_expression`, setting `tracker.jsx_mutable = true`. But when the parent `<div>` processes this child in `transform_jsx_children`, the expression is already a `_jsxSorted(...)` call. The `is_child_expression_immutable` check returns true for `_jsxSorted` calls, so the pre-set mutability signal is ignored.

2. **Missing spread/var_props/children_mutable propagation**: After `transform_jsx_element_inner` computes its own flags, it does NOT set `tracker.jsx_mutable` to signal the parent that this element's subtree is mutable. The parent's `transform_jsx_children` only sees `jsx_mutable` changes from is_fn component detection (line 1145), not from spread/var_props/children_mutable.

Additionally, fix `is_child_expression_immutable` for member expressions to match SWC behavior (member expressions on non-import objects should be mutable).

Output: Corrected flag=1 for parent elements with mutable subtrees, reducing flag mismatches from ~122 to under 50.
</objective>

There are two complementary bugs to fix. Both are in jsx_transform.rs.

**Bug A: Missing spread/var_props/children_mutable propagation to parent**

In SWC, `self.jsx_mutable = true` is set in `handle_jsx_props_obj` when `var_props_raw` is non-empty, and when children are mutable. The OXC code already sets `tracker.jsx_mutable` for non-immutable component tags (lines 1145-1158), but does NOT set it for spread/var_props/children_mutable. The parent's `transform_jsx_children` uses the save/restore pattern to detect child mutability via `tracker.jsx_mutable`, but the child element never sets it for these cases.

**Fix A1: In `transform_jsx_element_inner`**, after the flags bitfield computation (after `if static_subtree { flags |= 2; }` around line 1480) and BEFORE the key generation comment (`// Generate key:`), add:

```rust
// Propagate mutability to parent element via tracker.jsx_mutable.
// In SWC, var_props existence sets self.jsx_mutable = true (transform.rs line 1469),
// which propagates to the parent's static_subtree check via the save/restore pattern
// in transform_jsx_children.
if has_spread || !var_props.is_empty() || children_mutable {
    tracker.jsx_mutable = true;
}
```

**Fix A2: In `transform_jsx_fragment_inner`**, after the flags bitfield computation (after `if static_subtree { flags |= 2; }`) and BEFORE the key generation:

```rust
// Propagate children mutability to parent via tracker.jsx_mutable.
if children_mutable {
    tracker.jsx_mutable = true;
}
```

**Bug B: Pre-set jsx_mutable from exit_expression is ignored in ExpressionContainer path**

When JSX elements are nested inside non-JSX expression containers (e.g., `{cond ? <p/> : <Stuff/>}`), OXC's bottom-up traversal processes inner elements first via `exit_expression`. When `<Stuff/>` is transformed, it sets `tracker.jsx_mutable = true` (via the is_fn check at line 1145).

Later, when the parent element is processed, `transform_jsx_children` handles the ternary expression through the `JSXChild::ExpressionContainer -> other` branch. This branch does NOT save/restore `tracker.jsx_mutable` (save/restore only happens for direct `JSXChild::Element` and `JSXChild::Fragment` cases). So `tracker.jsx_mutable` is still true from the inner element's exit_expression. However, the `other` branch only checks `is_child_expression_immutable` -- it never checks `tracker.jsx_mutable`.

**Fix B: In `transform_jsx_children`**, in the `other =>` branch (around line 1907), immediately BEFORE the `if !is_child_expression_immutable(&other)` check at line ~1991, add:

```rust
// Check if tracker.jsx_mutable was set by an inner JSX element
// that was already transformed by exit_expression (bottom-up).
// This happens when JSX elements are nested inside non-JSX
// expressions like ternaries or logical &&.
// Example: {cond ? <p/> : <Stuff/>} -- <Stuff/>'s exit_expression
// set jsx_mutable, and we need to pick it up here.
if tracker.jsx_mutable {
    any_child_mutable = true;
    // Reset so it doesn't leak to sibling expressions.
    // The parent will propagate via Fix A if needed.
    tracker.jsx_mutable = false;
}
```

This check goes AFTER the signal wrapping `continue` branches (WrapPropSignal, WrapPropNamed, _fnSignal) since those branches handle their own mutability and skip past this code via `continue`. It goes immediately before the `if !is_child_expression_immutable(&other)` check.

**Why all three fixes are needed together**:
- Fix A1/A2: When `transform_jsx_children` processes a direct `JSXChild::Element` or `JSXChild::Fragment`, the save/restore pattern captures the child's mutability via `tracker.jsx_mutable`. Fix A ensures the child actually SETS `tracker.jsx_mutable` for spread/var_props/children_mutable cases.
- Fix B: When inner JSX elements were already transformed by exit_expression and are now inside expression containers (ternary, logical, etc.), the pre-set `tracker.jsx_mutable` needs to be captured in the `other` branch.

  <name>Task 2: Fix is_child_expression_immutable for member expressions</name>
  <files>crates/qwik-optimizer-oxc/src/jsx_transform.rs</files>

**Root cause**: The `is_child_expression_immutable` function (line 126) treats ALL member expressions as immutable (lines 145-146: `Expression::StaticMemberExpression(_) | Expression::ComputedMemberExpression(_) => true`). But SWC's `ConstCollector` treats ALL member expressions as NOT const (`visit_member_expr` -> `is_const = false`). This causes expressions like `head.title`, `store.address.city.name`, `row.value.id` to get flag=3 in OXC but flag=1 in SWC.

However, we cannot make ALL member expressions mutable because `dep.thing` (where `dep` is an import) gets flag=3 in SWC. SWC wraps `dep.thing` as `_wrapProp(dep, "thing")` which is a const call. Since OXC does not do this wrapping for non-signal member expressions in children, we approximate: member expressions where the base object is a known import are immutable; all others are mutable.

**Implementation**:

1. **Change function signature** at line 126 to accept `module_imports`:

```rust
fn is_child_expression_immutable(expr: &Expression<'_>, module_imports: &[crate::types::ImportInfo]) -> bool {
```

2. **Replace lines 145-146** (the member expression arms) with:

```rust
Expression::StaticMemberExpression(member) => {
    // Member expressions: mutable by default (SWC ConstCollector.visit_member_expr).
    // Exception: if the base object is a known import identifier, treat as immutable.
    // SWC wraps import member access as _wrapProp(import, "prop") which is const.
    if let Expression::Identifier(obj_ident) = &member.object {
        let name = obj_ident.name.as_str();
        module_imports.iter().any(|imp| {
            imp.specifiers.iter().any(|spec| spec.local == name)
        })
    } else {
        false
    }
}
Expression::ComputedMemberExpression(member) => {
    if let Expression::Identifier(obj_ident) = &member.object {
        let name = obj_ident.name.as_str();
        module_imports.iter().any(|imp| {
            imp.specifiers.iter().any(|spec| spec.local == name)
        })
    } else {
        false
    }
}
```

3. **Update all recursive calls** within `is_child_expression_immutable` to pass `module_imports`:
   - `TemplateLiteral`: `is_child_expression_immutable(e, module_imports)`
   - `UnaryExpression`: `is_child_expression_immutable(&unary.argument, module_imports)`
   - `BinaryExpression`: both sides
   - `ConditionalExpression`: all three parts
   - `LogicalExpression`: both sides
   - `ParenthesizedExpression`: inner

4. **Update the call site** in `transform_jsx_children` at line ~1991:

```rust
if !is_child_expression_immutable(&other, module_imports) {
    any_child_mutable = true;
}
```

**Behavior summary**:
- `dep.thing` where `dep` is import -> immutable (flag=3) -- matches SWC
- `globalThing.thing` where `globalThing` is NOT import -> mutable (flag=1) -- matches SWC
- `head.title` where `head` is local const -> mutable (flag=1) -- matches SWC
- `store.address.city.name` where `store` is local const -> mutable (flag=1) -- matches SWC
- `signal.value` -> already handled by detect_signal_wrap, does not reach this function
- Bare identifiers (`signal`, `dep`, `globalThing`) -> still treated as immutable (no change; imperfect for unresolved globals but correct for the vast majority of cases)
