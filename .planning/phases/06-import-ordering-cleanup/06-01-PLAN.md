<objective>
Fix entry module import scoping: stop emitting segment-only imports in the entry module, fix the entry module body ordering to match SWC's assembly pattern, and merge multi-specifier Qwik core imports.

Purpose: The core import scoping bug causes ALL import_tracker flags to emit imports into the entry module even when they are only used by segment bodies (which become separate files). This adds extra imports like `_jsxSorted`, `useStore`, `mongodb`, etc. to the entry module. SWC avoids this via DCE (dead code elimination). OXC needs a targeted unused-import scanner. Additionally, SWC preserves multi-specifier imports like `import { useStore, mutable } from "@qwik.dev/core"` while OXC re-emits each specifier individually.
Output: Entry modules contain only imports that are actually referenced in the entry module code, with same-source specifiers merged.
</objective>

  <name>Task 1: Implement unused import filtering and body reordering for entry module</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
  The entry module's `exit_program` method (line ~2489) currently emits ALL framework imports flagged by `import_tracker` regardless of whether they're actually used in the entry module body. This causes segment-only imports to leak into the entry module.

  This task covers four tightly-coupled concerns that all operate in `exit_program` and share the `referenced_idents` set:
  (a) Building a referenced-identifiers helper
  (b) Filtering framework (synthetic) imports
  (c) Filtering user-code (non-Qwik) imports
  (d) Reordering the body assembly

  **1. Build a helper function to collect referenced identifiers from statements:**

  Create a function (near `exit_program` or as a separate helper) that scans a list of statements and returns a `HashSet<String>` of all identifier names used. It should skip import declarations themselves (we only want to see what the non-import code references).

  The simplest correct approach: for each non-import statement, recursively walk to find all `IdentifierReference` nodes and collect their names. This can be done with a simple recursive function that walks Statement/Expression/Pattern nodes collecting identifier names.

  **2. Modify exit_program to filter synthetic imports:**

  After the existing code that builds `new_stmts` (the synthetic framework imports and lazy import declarations) and before the body assembly, add filtering logic:

  a) Build new_stmts as before (no changes to existing logic)
  b) Split new_stmts into two groups:
     - `synthetic_imports`: The `import { X } from "@qwik.dev/core"` type statements
     - `lazy_imports_and_other`: The `const i_XXX = ...` lazy import declarations
  c) Scan old_body (non-import statements from the original program body) for referenced identifiers
  d) Also scan lazy_imports_and_other for references (e.g., lazy imports may reference `qrl`, so `qrl` import must be kept)
  e) Filter synthetic_imports to only those whose local specifier name is in the referenced identifiers set
  f) Keep lazy_imports_and_other as-is (always needed)

  **IMPORTANT:** Lazy import declarations (`const i_XXXX = ...`) are const declarations, not imports. They should NOT be filtered -- they are always needed (referenced by QRL calls in the old_body or segments).

  **3. Filter non-Qwik user imports in old_body:**

  When iterating old_body statements, if a statement is a non-Qwik import declaration, check if its specifiers are referenced in the REST of old_body (non-import statements). If not referenced, skip it.

  This requires collecting references from non-import statements first, then filtering import statements.

  **4. Reorder the body assembly to match SWC:**

  SWC's ordering is:
  1. Synthetic Qrl-suffixed imports (componentQrl, useStylesQrl, etc.) - insertion order
  2. Extra top items: lazy imports (const i_XXX) + hoisted functions (_hf0, _hf0_str)
  3. Original module body: non-Qwik imports (preserved), remaining code
  4. Extra bottom items (none currently)

  Reorder the assembly in exit_program:
  - First: Filtered Qrl-suffixed synthetic imports
  - Then: Other needed framework imports (qrl, inlinedQrl, _captures, etc.) -- only if referenced
  - Then: Lazy import declarations (const i_XXX)
  - Then: Original non-Qwik body (imports + code), with unused imports filtered

  **NOTE on ordering subtlety:** SWC emits synthetic imports in insertion order (the order `ensure_core_import()` was called during traversal). For simplicity, OXC can keep the current hardcoded order which closely matches. The critical fix is the FILTERING (removing segment-only imports), not the precise ordering of kept imports.

  - `issue_964.snap.new` should no longer have extra `_jsxSorted` in entry module

  <name>Task 3: Merge entry module non-dollar Qwik core specifiers by source</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
  After Tasks 1 and 2 filter non-dollar Qwik core specifiers to only those referenced in entry-module code, SWC preserves multi-specifier imports like `import { useStore, mutable } from "@qwik.dev/core"` while OXC re-emits each specifier as a separate `import { X } from "@qwik.dev/core"` statement.

  **IMP-03 Fix:** In the non-dollar specifier emission loop (the one modified in Task 2), instead of emitting one import statement per specifier, group kept specifiers by their source module and emit a single import statement per source with combined specifiers.

  **Implementation:**

  1. After filtering non-dollar specifiers (Task 2's `referenced_idents` check), collect the kept specifiers into a `HashMap<String, Vec<(String, String)>>` keyed by source module, where each value is a list of `(imported_name, local_name)` pairs.

  2. After collecting all kept specifiers, emit one import statement per source:
  ```rust
  // Group: { "@qwik.dev/core" => [("useStore", "useStore"), ("mutable", "mutable")] }
  for (source, specifiers) in &grouped_specifiers {
      // Build: import { useStore, mutable } from "@qwik.dev/core";
      let specifier_list = specifiers.iter()
          .map(|(imported, local)| {
              if imported == local {
                  local.clone()
              } else {
                  format!("{} as {}", imported, local)
              }
          })
          .collect::<Vec<_>>()
          .join(", ");
      // Emit the merged import statement
  }
  ```

  3. Sort specifiers within each merged import alphabetically by local name, to match SWC's output ordering.

  **Known SWC multi-specifier imports from research:**

  - `import { Slot, Fragment } from "@qwik.dev/core"` (1 snapshot)
  - `import { componentQrl, inlinedQrl, useStore, useLexicalScope } from "@qwik.dev/core"` (1 snapshot)

  **NOTE:** This merging applies ONLY to entry module non-dollar specifiers. Segment modules do NOT merge (SWC emits one import per identifier in segments -- this is handled correctly by Plan 06-02).

  **Test:** After this fix, snapshots with multi-specifier Qwik imports should show merged imports instead of individual ones.
