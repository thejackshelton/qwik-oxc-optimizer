  <name>Task 1: Implement QRL hoisting inside function bodies for loop contexts</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
  When a QRL call (e.g., `onClick$(() => ...)`) appears inside a loop body, SWC hoists the generated `qrl()` call to a `const` declaration at the top of the enclosing function body. OXC currently inlines the `qrl()` call at the usage site.

  **Affected snapshots:** `example_component_with_event_listeners_inside_loop`, `should_transform_nested_loops`, `should_transform_multiple_event_handlers`, `should_transform_multiple_event_handlers_case2`, and a few others.

  **Approach:** Use tuple storage `Vec<(String, String, Vec<String>)>` to buffer QRL hoists, then flush them at function exit. This avoids arena lifetime issues since `QwikTransform` does not carry the `'a` lifetime.

  **Step 1: Add hoisting buffer field to QwikTransform.**

  ```rust
  /// QRL declarations to hoist to the top of the enclosing function body.
  /// Each entry: (lazy_import_ident_name, segment_export_name, capture_names).
  /// Populated when exit_expression processes a dollar-call while loop_depth > 0.
  /// Flushed in exit_arrow_function_expression / exit_function.
  pending_loop_qrl_hoists: Vec<(String, String, Vec<String>)>,
  ```

  Initialize as `Vec::new()` in QwikTransform::new().

  **Step 2: Modify exit_expression dollar-call processing for loop contexts.**

  In the code path where a `$`-suffixed call is replaced with a `qrl()` call (the segment extraction logic), add a check for `self.loop_depth > 0`. When inside a loop:

  a) Build the `qrl()` call expression components as usual (you already have the lazy import identifier name like `i_HASH`, the segment export name, and the capture list).
  b) Push `(lazy_import_ident.to_string(), segment_name.to_string(), capture_names.clone())` to `self.pending_loop_qrl_hoists`.
  c) Instead of placing the `qrl()` call expression inline, replace the original `$()` call with an identifier reference to `segment_name`:
     ```rust
     *expr = ctx.ast.expression_identifier_reference(SPAN, ctx.ast.atom(&segment_name));
     ```

  The key insight: the segment export name (e.g., `Foo_component_div_button_onClick_XXXXXXXXXXXX`) becomes both the const variable name for the hoisted declaration AND the identifier reference at the call site.

  **Step 3: Flush hoists in exit_arrow_function_expression.**

  In `exit_arrow_function_expression`, after the existing `root_jsx_mode` restore logic, check for pending hoists:

  ```rust
  if !self.pending_loop_qrl_hoists.is_empty() {
      let hoists = std::mem::take(&mut self.pending_loop_qrl_hoists);
      let body = &mut arrow.body;

      // Build const declarations from stored components and prepend to body
      let mut new_stmts = ctx.ast.vec_with_capacity(hoists.len() + body.statements.len());
      for (import_ident, seg_name, captures) in hoists {
          // Build: const seg_name = /* @__PURE__ */ qrl(import_ident, "seg_name", [captures]);
          let qrl_call = build_qrl_call_expr(&import_ident, &seg_name, &captures, ctx);
          let const_decl = build_const_declaration(&seg_name, qrl_call, ctx);
          new_stmts.push(const_decl);
      }
      // Append original body statements after hoisted declarations
      for stmt in body.statements.drain(..) {
          new_stmts.push(stmt);
      }
      body.statements = new_stmts;
  }
  ```

  **Step 4: Add the same logic to exit_function (for regular function expressions).**

  Some components use `function` keyword instead of arrows. Add the same flush logic in `exit_function` if that hook exists, or ensure the function body case is handled.

  **Step 5: Handle edge case -- arrow body is expression-form (not block).**

  If the arrow function has an expression body (e.g., `() => expr`), it should already have been converted to block form by the transform. Verify this. If not, convert to block form before prepending.

  Also create `build_const_declaration`:
  ```rust
  fn build_const_declaration<'a>(
      name: &str,
      init: Expression<'a>,
      ctx: &mut TraverseCtx<'a, ()>,
  ) -> Statement<'a> {
      // Build: const name = init;
  ```

  <name>Task 2: Fix entry module lazy import ordering</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
  SWC uses `extra_top_items: BTreeMap<Id, ...>` which automatically sorts entries by Id (alphabetical by name). This means lazy imports (`const i_XXX = ...`) appear sorted by their variable name.

  OXC's `import_tracker.lazy_imports: Vec<(String, String)>` stores lazy imports in the order they were encountered during traversal. This may differ from SWC's sorted order.

  **Fix:** In `exit_program`, sort `self.import_tracker.lazy_imports` by the import path (second element of the tuple) before emitting them:

  ```rust
  // Sort lazy imports by import path to match SWC's BTreeMap ordering
  self.import_tracker.lazy_imports.sort_by(|a, b| a.1.cmp(&b.1));
  ```

  This sorts by the full import path which is what SWC's BTreeMap keys produce (the variable names `i_HASH` are derived from segment paths, and BTreeMap sorts by key).

  From the `example_component_with_event_listeners_inside_loop` diff:
  - SWC order: `loopArrowFn_span_click`, `loopForI_span_click`, `loopForOf_span_click`, etc. (alphabetical by segment path)
  - OXC order: `loopWhile_span_click`, `loopForI_span_click`, `div_button_click`, etc. (traversal order)

  **Implementation:** In `exit_program`, before the lazy import emission loop (line ~2598), add the sort call. This is a one-line fix.

  Also verify the entry module body assembly order after Plans 01/02:
  1. Qrl-suffixed imports (componentQrl, etc.) -- filtered by Plan 01
  2. Framework utility imports (qrl, inlinedQrl, etc.) -- filtered by Plan 01
  3. Lazy import declarations (const i_XXX) -- sorted here
  4. Non-dollar Qwik core specifiers (useStore, etc.) -- filtered and merged by Plan 01
  5. Original body (non-Qwik imports + code)
