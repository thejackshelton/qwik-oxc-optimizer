let hoisted_stmts: Vec<(String, String)> = qwik_transform.hoisted_function_stmts().to_vec();

<task type="auto">
  <name>Task 2: Fix _fnSignal false-positive import and per-segment _hf* filtering (GAP-7 + bonus)</name>
  <files>crates/qwik-optimizer-oxc/src/code_move.rs</files>
  <action>
Two changes in code_move.rs:

**Change 1 (GAP-7): Remove _fnSignal false-positive check at line 106.**

Change:
```rust
if body_code.contains("_fnSignal") || !hoisted_stmts.is_empty() {
```
To:
```rust
if body_code.contains("_fnSignal") {
```

The `|| !hoisted_stmts.is_empty()` condition was a proxy: "if any hoisted stmts exist globally, this segment probably needs _fnSignal." But hoisted stmts existing globally doesn't mean THIS segment uses _fnSignal. The `body_code.contains("_fnSignal")` check is sufficient -- if the segment body contains `_fnSignal(` calls, it needs the import; if it doesn't, it shouldn't get the import.

**Change 2 (per-segment _hf* filtering): Filter hoisted stmts at lines 269-273.**

Change:
```rust
// --- Phase 5: Hoisted function declarations ---
for (fn_code, str_code) in hoisted_stmts {
    parts.push(fn_code.clone());
    parts.push(str_code.clone());
}
```
To:
```rust
// --- Phase 5: Hoisted function declarations (filtered per-segment) ---
// Only inject _hf* declarations that this segment's body actually references.
// SWC injects ALL extra_top_items then relies on DCE to remove unused ones.
// We filter upfront since OXC has no DCE.
for (fn_code, str_code) in hoisted_stmts {
    // Extract variable name from "const _hfN = ..." pattern
    if let Some(var_name) = fn_code
        .strip_prefix("const ")
        .and_then(|s| s.split(|c: char| c == ' ' || c == '=').next())
    {
        if body_code.contains(var_name) {
            parts.push(fn_code.clone());
            parts.push(str_code.clone());
        }
    } else {
        // Fallback: include if we can't parse the variable name
        parts.push(fn_code.clone());
        parts.push(str_code.clone());
    }
}
```

The variable name extraction is robust because the `const _hfN = ...` format is stable -- generated by `hoist_fn_signal_call` with a monotonic counter. The `body_code.contains("_hf0")` check works because _fnSignal calls reference `_hf0` literally (e.g., `_fnSignal(_hf0, [deps], "expr")`).

Ordering note: The push order already matches SWC's BTreeMap ordering (monotonic counter produces `_hf0, _hf0_str, _hf1, _hf1_str` which is alphabetical).
