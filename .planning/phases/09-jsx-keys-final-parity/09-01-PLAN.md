**Const assignment (25 files):**
When a `$()` call is the init of a VariableDeclarator (e.g. `const Header = $((...) => ...)`), the replacement `qrl(i_XXX, "name")` must preserve the surrounding `const Header =` binding. Currently OXC replaces the `$()` CallExpression with the qrl call but somehow loses the variable binding context.

Investigate `exit_expression` in transform.rs around lines 2568-2648 where `$()` calls are replaced. The issue is likely that when the replacement expression is built, it replaces the VariableDeclarator's init but the VariableDeclaration itself gets dropped or the expression is hoisted out of the declarator context.

SWC's `fold_var_decl_or_expr` (lines ~1400-1470) wraps the qrl call result back into the original VariableDeclaration. OXC needs to do the same: when replacing a `$()` that is the init of a const/let/var declarator, emit `const X = qrl(...)` not just `qrl(...)`.

Look at how `emit_mode` or `entry_strategy` affects this — SWC does this for all strategies.

Also check: the `example_exports` test shows OXC dropping complex destructured exports like `export const [a, {b, v1: [c], d = v2, ...e}] = thing`. SWC preserves these. This may be the same root cause (variable declarations being dropped).

**Entry field (8 files):**
In `lib.rs` around line 380, `entry` is hardcoded to `None`. Change this to compute entry from the strategy:
- For `EntryStrategy::Inline` and `EntryStrategy::Hoist`: `entry = Some("entry_segments".into())`
- For `EntryStrategy::Segment`: `entry = None`

Reference SWC's `entry_strategy.rs` `get_entry_for_sym()` method to understand the logic.

Also fix the `(ENTRY)` marker in segment output headers. SWC adds `(ENTRY)` only for segment strategy; for Inline/Hoist, segments are embedded. Check where the segment module header string is built and conditionally add `(ENTRY)` only for the Segment strategy, not Inline/Hoist.

Wait — the diff shows the OPPOSITE: SWC has NO `(ENTRY)` marker but OXC adds `(ENTRY)` for Inline strategy tests. Check the test output format in `test.rs` to see how `(ENTRY)` is determined. In the SWC golden snapshots, `(ENTRY)` appears only when the entry field is non-null. So fixing the entry field should automatically fix the `(ENTRY)` marker IF the test rendering code uses the entry field.

**Windows paths (1 file):**
In `support_windows_paths` test, the origin field shows `components\\apps\\apps.tsx` (OXC) vs `components/apps/apps.tsx` (SWC), and the key hash is `9H` (OXC) vs `KD` (SWC). Normalize backslashes to forward slashes:
1. In the `origin` field computation (transform.rs or lib.rs)
2. In the hash input (the path string used for hash computation)
3. In the segment module filename (shown as `components\apps\apps.ts` vs `components/apps/apps.ts`)

Search for where `rel_path` or `origin` is computed and add `.replace('\\', '/')` or equivalent Rust string replacement.

35 snapshot files show `onClick$={...}` (OXC) where SWC has `q-e:click={...}`. This is the JSX event name transform that converts user-facing `onClick$` into the Qwik-internal `q-e:click` attribute name.

SWC transforms event handler attribute names during JSX processing (in `convert_signal_word`/`convert_to_getter` or equivalent). The OXC code already does this for some cases (the transform was implemented in Phase 4-5), but it appears to miss certain cases.

Investigate which specific patterns are missed:
1. Check `example_default_export_index`: the `onClick$=` appears in the ENTRY module output (not a segment). This suggests the transform runs on segments but not on the entry module's remaining JSX.
2. Check `example_jsx_listeners`: Shows multiple event handlers not transformed.
3. Check `example_prod_node`: Shows event naming in prod mode.

The fix likely involves ensuring that the `onClick$` -> `q-e:click` transform runs in ALL JSX contexts, not just within extracted segments. Check if there's a condition that gates the transform to only run inside `$()` boundaries.

Also check the `q-e:` prefix generation: SWC uses `convert_signal_word` to convert `onClick` -> `click`, then prepends `q-e:`. The `$` suffix should be stripped first. Verify OXC does the same conversion.

For `bind:` events (`should_merge_bind_checked_and_on_input` etc.), these show `onInput$` vs `q-e:input` — same issue.

If the transform is already implemented but gated, remove the gate. If not implemented for the entry module path, add it.
  </action>

1. `example_default_export_index` shows `q-e:click` not `onClick$`
2. `example_jsx_listeners` shows transformed event names
3. `should_merge_bind_*` tests show `q-e:input` not `onInput$`
  </verify>
