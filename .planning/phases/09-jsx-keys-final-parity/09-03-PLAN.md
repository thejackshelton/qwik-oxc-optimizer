  <action>
When `EmitMode::Dev` is active, SWC emits different QRL functions with source location metadata:

1. `qrl(...)` → `qrlDEV(import_fn, "name", { file: "/path", lo: N, hi: N, displayName: "..." })`
2. `inlinedQrl(...)` → `inlinedQrlDEV(callback, "name", { file: "/path", lo: N, hi: N, displayName: "..." }, [captures])`
3. `_noopQrl("name", [captures])` → `_noopQrlDEV("name", { file: "/path", lo: 0, hi: 0, displayName: "..." }, [captures])`

Also in dev mode, JSX elements get extra source location props:
```js
{ fileName: "test.tsx", lineNumber: N, columnNumber: N }
```

**Implementation steps:**

1. Find where `qrl()` calls are built in transform.rs (the `build_qrl_call` or similar function). Add a check for `self.options.emit_mode == EmitMode::Dev`.

2. When dev mode:
   - Change the callee from `qrl` to `qrlDEV` (or `inlinedQrlDEV`, `_noopQrlDEV`)
   - Add a third argument: an ObjectExpression with properties:
     - `file`: StringLiteral with the absolute file path (`self.options.path`)
     - `lo`: NumericLiteral with the span start byte offset
     - `hi`: NumericLiteral with the span end byte offset
     - `displayName`: StringLiteral with the display name

3. For `_noopQrl` → `_noopQrlDEV`: Same metadata object, but lo/hi are always 0.

4. For JSX dev locations: After each `_jsxSorted`/`_jsxSplit` call in dev mode, add an extra argument with `{ fileName, lineNumber, columnNumber }`. Check SWC's dev mode JSX emission for the exact format.

5. Update the `needs_qrl`/`needs_inlined_qrl`/`needs_noop_qrl` import tracking to use the `DEV` variants when `EmitMode::Dev`.

6. The `serverQrl` import source differs in dev mode: check `example_drop_side_effects` which shows `import { serverQrl } from "@qwik.dev/router"` (SWC) vs `import { serverQrl } from "@qwik.dev/core"` (OXC). This may be a separate issue from dev mode — the import source for `serverQrl` should come from `@qwik.dev/router`, not core.

**Affected tests:** `example_dev_mode`, `example_dev_mode_inlined`, `example_noop_dev_mode`, `example_drop_side_effects`, `example_jsx_keyed_dev`
  </action>

**FIRST: Read 09-02-SUMMARY.md** to understand which _wrapProp/_fnSignal/_rawProps transforms were completed. Many capture diffs auto-resolve once _rawProps is used. Only fix capture issues that remain AFTER plan 02's transforms are in place.

**Capture analysis (27 files):**
Multiple patterns of capture list differences:

1. **Missing captures (functions/classes):** `example_capturing_fn_class` shows SWC capturing `Thing` and `hola` (class and function) with error diagnostics, while OXC has empty captures and no errors. SWC captures these references and emits C02 error diagnostics. OXC needs to:
   - Detect function declarations and class declarations referenced inside `$()` bodies
   - Add them to the capture list (even though they're invalid)
   - Emit C02 diagnostic errors for them

2. **_rawProps vs individual captures:** `example_multi_capture` shows SWC using `[_rawProps]` capture but OXC using `[aaa, arg0, foo]`. When a segment accesses props, SWC captures the whole `_rawProps` object, not individual prop values. This is tied to the _rawProps transform from plan 02 — once _rawProps is used, the capture should be `[_rawProps]` not individual destructured props.

3. **Extra/missing captures:** `should_transform_nested_loops` shows SWC capturing `[row]` where OXC doesn't capture at all. Iteration variable captures from loop contexts need to be included.

4. **Capture metadata:** Some tests show `"captures": true` (SWC) vs `"captures": false` (OXC) and vice versa. Also `captureNames` arrays differ.

5. **should_extract_single_qrl_with_index:** Shows capture of `_captures[0]` pattern — verify capture indexing.

After plan 02's _rawProps and _fnSignal fixes, many capture diffs should auto-resolve. Focus on:
- Function/class reference detection and C02 diagnostics
- Iteration variable capture inclusion
- Any remaining capture ordering issues

**Dead code elimination (3 files):**
1. `example_dead_code`: SWC strips the body of `useMount$(() => {})` down to `useMount$(() => {})` (empty body), but preserves the `import { deps } from "deps"` and `if (false) { deps(); }` in the segment body. OXC drops the import and the if-false block. Match SWC's behavior: preserve dead code inside segment bodies (don't apply DCE to segment function bodies).

2. `example_strip_client_code` / `example_strip_server_code`: These involve `isServer`/`isBrowser` conditional stripping. SWC replaces `isServer` with `true`/`false` and then the minifier removes dead branches. Check if OXC is doing any premature stripping.

**Body code differences (5 files):**
- `example_8`: SWC preserves destructuring `const { something, styff } = hola` and assignment `const hello = hola.nothere.stuff[global]` in segment body. OXC drops these. This may be the same const-assignment issue from plan 01.
- `example_9`: SWC preserves `let decl8 = 1, decl9;` and `function decl10(...)` in segment body. OXC drops them.

These body code diffs suggest that OXC's segment body construction (code_move.rs) is stripping declarations that SWC preserves. Check the `create_segment_body` or equivalent function and ensure all non-captured declarations are preserved in the segment body.
