**Part A: De-duplicate placeholder param names (CRITICAL)**

SWC uses `private_ident!("_")` for both event and element placeholders when padding param_names in `transform_event_handler_with_iter_var`. SWC's codegen automatically de-duplicates identifiers with the same name but different syntax contexts, producing `_` for position 0 and `_1` for position 1. OXC stores param_names as plain strings, so pushing `"_"` twice produces `["_", "_", "row"]` which would render as `(_, _, row)` -- a duplicate parameter name that diverges from SWC's `(_, _1, row)`.

**Fix location:** Around line 1172-1176, where `param_names` is padded to length 2 inside the `if !used_iter_vars.is_empty()` block:

```rust
// Current code (WRONG -- produces duplicate "_"):
while param_names.len() < 2 {
    param_names.push("_".to_string());
}
```

Replace with de-duplicating logic that matches SWC's codegen behavior:

```rust
// Ensure at least 2 params (event, element).
// SWC uses private_ident!("_") for both, and codegen de-duplicates
// to "_", "_1". We must do the same for plain strings.
while param_names.len() < 2 {
    let placeholder = if param_names.iter().any(|n| n == "_") {
        "_1".to_string()
    } else {
        "_".to_string()
    };
    param_names.push(placeholder);
}
```

This handles the common case: if position 0 already has a named param (e.g., `ev`), position 1 gets `_`. If position 0 is `_` (the most common case for event handlers with `() =>` signatures where both are placeholders), position 1 gets `_1`. This matches SWC's de-duplication behavior.

The approach:

2. If so, build the param string: join all param_names with ", " (e.g., `"_, _1, row"` or `"_, _1, row, idx"`)
3. Find the `=>` arrow in the body code using the existing `find_arrow_position()` helper

Then implement `inject_iteration_params`:

```rust
/// Inject iteration variable parameters into an arrow function's parameter list.
///
/// For a body like `() => { ... }`, replaces the params to get `(_, _1, row) => { ... }`.
/// Uses param_names which has format [event_placeholder, element_placeholder, iter_var1, ...].
fn inject_iteration_params(body_code: &str, param_names: &[String]) -> String {
    if let Some(arrow_pos) = find_arrow_position(body_code) {
        // Find the parameter list: everything before `=>`
        let before_arrow = &body_code[..arrow_pos];
        let after_arrow = &body_code[arrow_pos..]; // includes "=> ..."

        // Find the opening paren of params
        // The body_code starts with the function expression, e.g., "() => ..." or "(ev) => ..."
        // We need to replace everything from first "(" to last ")" before the arrow
        if let Some(open_paren) = before_arrow.find('(') {
            // Find the matching close paren by scanning backwards in the UNTRIMMED
            // before_arrow string. Using trimmed would produce an index into the
            // trimmed view, which is incorrect for the original string when there's
            // whitespace (e.g., async arrow functions or trailing spaces before =>).
            if let Some(close_paren_pos) = before_arrow.rfind(')') {
                let param_str = param_names.join(", ");
                let prefix = &body_code[..open_paren + 1]; // up to and including "("
                // Reconstruct: prefix + new_params + ")" + anything between ")" and "=>" + "=>"...
                let between = &before_arrow[close_paren_pos + 1..arrow_pos];
                return format!("{}{}){}{}", prefix, param_str, between, after_arrow);
            }
        }
    }
    body_code.to_string()
}
```

**Important edge cases:**
- The body_code might be `() => console.log(row.value.id)` (expression body)
- The body_code might be `() => {\n  ...\n}` (block body)
- async arrow functions: `async () => ...` -- the `(` comes after `async `. Using `before_arrow.rfind(')')` (not trimmed) correctly finds the `)` position in the original string
- The existing `find_arrow_position` already handles nested parens and strings

**Interaction with capture injection:** The param injection must happen BEFORE `inject_captures_into_body` since that function also uses `find_arrow_position`. If params are injected first, the arrow position may shift. To keep things clean, apply param injection first, then pass the result to capture injection.
