Two related fixes to unblock _fnSignal wrapping in cases where OXC incorrectly rejects:

**1. Harmless globals (undefined, NaN, Infinity):**

In `collect_reactive_deps_inner`, the `Expression::Identifier` arm (around line 814) currently treats ALL KNOWN_GLOBALS identically — setting `has_non_reactive_non_const = true`. But `undefined`, `NaN`, and `Infinity` are effectively const values (like literals) and should NOT block wrapping.

Change the globals handling to distinguish harmless vs side-effect globals:

```rust
if crate::collector::KNOWN_GLOBALS.contains(name) {
    // Harmless constant-like globals should NOT block wrapping.
    // SWC's IdentCollector treats these as non-scope variables and
    // they don't appear in scoped_idents, so they don't trigger
    // contains_side_effect.
    let is_harmless_global = matches!(name, "undefined" | "NaN" | "Infinity");
    if !is_harmless_global {
        *has_non_reactive_non_const = true;
    }
    return;
}
```

Apply the same fix in the `StaticMemberExpression` arm (around line 758) where globals are also checked:

```rust
if crate::collector::KNOWN_GLOBALS.contains(root_name.as_str()) {
    let is_harmless_global = matches!(root_name.as_str(), "undefined" | "NaN" | "Infinity");
    if !is_harmless_global {
        *has_non_reactive_non_const = true;
    }
    return;
}
```

**2. accept_call_expr for props:**

SWC's `convert_to_getter` (used for JSX props) calls `create_synthetic_qqsegment(expr, true)` where `accept_call_expr=true`. This means SWC wraps expressions containing function calls when they're in a PROP context. OXC's `contains_function_call` check blocks this.

In the prop wrapping path (around line 1780), remove the `contains_function_call` gate. Replace:

```rust
} else if !contains_function_call(&value) {
```

with:

```rust
} else {
```

This allows `collect_reactive_deps` to analyze the full expression including calls. The `has_non_reactive` flag from `collect_reactive_deps` already provides the correct bailout — if the call expression references a global (like `$localize`) or import, it sets `has_non_reactive_non_const = true` and wrapping is skipped. If the call only uses reactive deps, wrapping proceeds.

For the CHILDREN path (around line 2565-2566), keep the `!contains_function_call` check. SWC uses `accept_call_expr=false` for `convert_to_signal_item` (children), which means call expressions in children DO skip wrapping. But also add TaggedTemplateExpression to `contains_function_call`:

```rust
Expression::TaggedTemplateExpression(_) => true,
```

TaggedTemplateExpression is semantically a function call (the tag is called with the template parts). Adding it ensures children with tagged templates skip _fnSignal wrapping, matching SWC's behavior where tagged templates are treated as calls.

The CORRECT behavior for props with tagged templates: SWC's `accept_call_expr=true` means call expressions ARE processed, but TaggedTemplateExpression bodies with free globals like `$localize` still prevent wrapping via the side-effect/global check. The fix:
