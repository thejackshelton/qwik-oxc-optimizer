  <action>
In `collect_reactive_deps_inner`, the `StaticMemberExpression` branch (around line 807) has:

```rust
if has_chain_depth(expr, 2) {
```

This requires `ident.prop.subprop` (depth 2) to classify as a store dep. But SWC treats ANY
local `ident.prop` (depth 1) as a scoped variable that becomes a reactive dep if not an import
or global.

Change this to:

```rust
if has_chain_depth(expr, 1) {
```

This allows `panelStore.active` (depth 1) to be classified as a reactive dep, matching SWC.

CRITICAL: Verify this does NOT cause regressions. The depth check exists to prevent treating
simple member expressions like `Math.random` as reactive deps, but `Math` is already handled
by the `KNOWN_GLOBALS` check above this point. And imports are handled by `is_imported_identifier`.
So by the time we reach the depth check, the identifier is confirmed to be:
- Not a destructured prop alias
- Not _rawProps or props param
- Not an import
- Not a known global

This means it's a local variable, and ANY member access on a local variable is potentially
reactive (signal.value, store.prop, etc.). Depth 1 is correct.

Actually, reconsider: `has_chain_depth(expr, 1)` means the expression itself has depth >= 1,
which is always true for any `StaticMemberExpression`. The check becomes redundant.

Looking at the code flow more carefully: the branch at line 807 is ONLY reached when:
1. We're in a StaticMemberExpression
2. The property is NOT "value" (handled earlier at line 725)
3. The root identifier is NOT _rawProps or props_param_name (handled at line 776-789)
4. The root identifier is NOT an import (handled at line 791-796)
5. The root identifier is NOT a known global (handled at line 798-805)

At this point, we have a local variable with a member access that isn't `.value`. This IS
a store-like access pattern. Changing to depth 1 or removing the check entirely is correct.

Change `has_chain_depth(expr, 2)` to `has_chain_depth(expr, 1)` on that line. Since any
StaticMemberExpression has at least depth 1, this is equivalent to removing the check, but
keeping it as depth 1 is more explicit about intent.
