In `enter_export_default_declaration` (around line 2068), after the existing stack_ctxt logic,
add detection for inline component patterns.

The pattern to detect:
1. The ExportDefaultDeclaration's declaration is an Expression
2. That expression is an ArrowFunctionExpression (or wrapped in TSAsExpression, etc.)
3. The arrow function's first parameter is an ObjectPattern (destructured props)
4. The arrow function body contains JSX (this is what makes it an "inline component")

For simplicity, detect conditions 1-3 and set up `active_props_info`. Condition 4 (JSX
presence) is implicitly handled: if there's no JSX, the _rawProps rewrite is harmless.

Implementation:

```rust
fn enter_export_default_declaration(
    &mut self,
    decl: &mut ExportDefaultDeclaration<'a>,
    _ctx: &mut TraverseCtx<'a, ()>,
) {
    // ... existing stack_ctxt logic ...

    // Detect inline component pattern: export default ({ data }) => ...
    // SWC rewrites destructured props to _rawProps for inline components too.
    if let ExportDefaultDeclarationKind::Expression(expr) = &decl.declaration {
        // Unwrap TS type assertions to get the arrow function
        let maybe_arrow = unwrap_ts_expression(expr);
        if let Expression::ArrowFunctionExpression(arrow) = maybe_arrow {
            let import_names: HashSet<String> = self
                .collected
                .module_imports
                .iter()
                .flat_map(|imp| imp.specifiers.iter().cloned())
                .collect();
            let info = props_destructuring::analyze_props_destructuring(
                &arrow.params,
                &import_names,
            );
            if info.needs_transform {
                self.active_props_info = Some(info);
            }
        }
    }
}
```

```rust
fn exit_export_default_declaration(
    &mut self,
    decl: &mut ExportDefaultDeclaration<'a>,
    ctx: &mut TraverseCtx<'a, ()>,
) {
    // ... existing stack_ctxt truncation ...

    // Inline component _rawProps rewrite
    let props_info = self.active_props_info.take();
    if let Some(ref info) = props_info {
        if info.needs_transform {
            if let ExportDefaultDeclarationKind::Expression(expr) = &mut decl.declaration {
                // Get mutable reference to the arrow function
                if let Expression::ArrowFunctionExpression(arrow) = expr {
                    // 1. Replace the destructured parameter with _rawProps
                    if !arrow.params.items.is_empty() {
                        let new_pattern = ctx.ast.binding_pattern_binding_identifier(
                            SPAN,
                            ctx.ast.atom(&info.raw_props_name),
                        );
                        let new_param = ctx.ast.formal_parameter(
                            SPAN,
                            ctx.ast.vec(),
                            new_pattern,
                            None::<oxc::allocator::Box<'a, TSTypeAnnotation<'a>>>,
                            None::<oxc::allocator::Box<'a, Expression<'a>>>,
                            false,
                            None,
                            false,
                            false,
                        );
                        arrow.params.items[0] = new_param;
                        arrow.params.rest = None;
                    }

                    // 2. If rest pattern: insert const rest = _restProps(_rawProps, [...])
                    if let Some(ref rest_name) = info.rest_name {
                        self.import_tracker.needs_rest_props = true;
                        let excluded_keys: Vec<String> =
                            info.prop_keys.iter().map(|(key, _)| key.clone()).collect();
                        let rest_stmt = props_destructuring::build_rest_props_declaration(
                            rest_name,
                            &info.raw_props_name,
                            &excluded_keys,
                            ctx,
                        );
                        let mut old_stmts = ctx.ast.vec();
                        std::mem::swap(&mut arrow.body.statements, &mut old_stmts);
                        let mut new_stmts = ctx.ast.vec_with_capacity(1 + old_stmts.len());
                        new_stmts.push(rest_stmt);
                        for s in old_stmts {
                            new_stmts.push(s);
                        }
                        arrow.body.statements = new_stmts;
                    }

                    // 3. Rewrite body references: data -> _rawProps.data
                    let prop_map: Vec<(String, String)> = info
                        .prop_keys
                        .iter()
                        .map(|(key, local)| (local.clone(), key.clone()))
                        .collect();

                    if !prop_map.is_empty() {
                        props_destructuring::rewrite_body_statements(
                            &mut arrow.body.statements,
                            &prop_map,
                            &info.raw_props_name,
                            &info.prop_defaults,
                            ctx,
                        );
                    }
                }
            }
        }
    }
}
```

EDGE CASE: The arrow function may have an expression body (not a block body). For example:
`export default ({ data }) => (<div .../>)`. In this case, `arrow.body.statements` may be
empty if OXC represents expression bodies differently. Check the OXC AST: `arrow.expression`
flag indicates an expression body. The expression body is stored as a single
ExpressionStatement in `arrow.body.statements`. The `rewrite_body_statements` function should
handle this since it processes all statements recursively.

However, there's a subtlety: by the time `exit_export_default_declaration` runs, the JSX
transform has ALREADY converted JSX elements into `_jsxSorted(...)` calls using the
`destructured_props` info from `active_props_info`. The JSX transform used `_rawProps` as
the dep root_name. NOW, `rewrite_body_statements` replaces `data` -> `_rawProps.data` in
the body. But the JSX transform already emitted `_rawProps` as an identifier in the
`_jsxSorted` arguments (dep array, captures array, etc.).

This should work because:
- The JSX transform writes `_rawProps` as dep names (correct)
- `rewrite_body_statements` rewrites `data` in non-JSX parts (correct)
- The JSX-transformed parts already use `_rawProps` (via the dep collection logic)

The ONLY concern is: the already-transformed `_jsxSorted(...)` call in the body may contain
`_rawProps` identifiers that `rewrite_body_statements` shouldn't touch. But since `_rawProps`
is NOT in the `prop_map` (the prop_map maps local aliases like "data" to original keys like
"data"), `rewrite_body_statements` won't touch `_rawProps` references. It will only replace
the original alias `data` where it still appears — which is in the non-JSX parts of the body.

Actually, there IS an issue: the `_jsxSorted(...)` call contains the expression values from
JSX attributes. If the expression was `data.selectedOutputDetail`, and the JSX transform
already processed it (e.g., wrapped it with _fnSignal using `_rawProps` as dep), then
`rewrite_body_statements` would see the already-transformed version and NOT find `data`
(because it's been replaced by the _fnSignal call with `_rawProps`). Good — no double rewrite.

But if the JSX transform did NOT wrap the expression (because it decided not to), then
`data.selectedOutputDetail` is still in the _jsxSorted arguments. Then
`rewrite_body_statements` would rewrite `data` -> `_rawProps.data`, giving
`_rawProps.data.selectedOutputDetail`. This is also correct!

TIMING: Make sure the `active_props_info.take()` call happens at the right time. If
`active_props_info` is consumed (taken) in `exit_export_default_declaration`, it won't
be available for any nested processing. But since the JSX transform already used it

- Replace standalone `{local_alias}` with `_rawProps.{original_key}` in the body string.

- Input body: `data.selectedOutputDetail = "options"`

Implementation sketch in `exit_export_default_declaration`, after `rewrite_body_statements`:

```rust
// 4. Post-process segment body strings: replace prop aliases with _rawProps.{alias}
// Segment bodies are captured from source text BEFORE the AST rewrite,
// so they still contain the original destructured prop aliases.
for (_span, body_code) in self.segment_body_codes.iter_mut() {
    for (original_key, local_alias) in &info.prop_keys {
        let replacement = format!("{}.{}", info.raw_props_name, original_key);
        *body_code = replace_identifier_in_body(body_code, local_alias, &replacement);
    }
}
```

The `replace_identifier_in_body` function should do word-boundary-aware replacement:
- Match `local_alias` only at word boundaries (preceding char is not alphanumeric/underscore,

- Replace with `_rawProps.{original_key}`

This can be a simple standalone function in transform.rs, or you can import/reuse

Insert this code after the `KNOWN_GLOBALS` check and before the `has_chain_depth` check:

```rust
// Check if root_name is a destructured prop alias (e.g., `data` from `{ data }` destructuring).
// If so, push `_rawProps` as the dep instead of `data`, same as the Identifier branch.
if let Some(props) = destructured_props {
    for (local_alias, _original_key) in props {
        if local_alias == root_name.as_str() {
            if !seen.contains("_rawProps") {
                let param = format!("p{}", primary_deps.len());
                seen.insert("_rawProps".to_string());
                primary_deps.push(ReactiveDep {
                    root_name: "_rawProps".to_string(),
                    param_name: param,
                });

            return;
        }
    }

```
