<task type="auto">
  <name>Task 1: Reverse props capture reclassification for child segments</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
The current code at exit_call_expression for component$ (lines ~3011-3049) does this:
1. Builds `local_aliases` from `info.prop_keys` (the destructured prop names like foo, bar)
2. For each child segment whose parent matches this component: REMOVES captures matching local_aliases, adds _rawProps

This is backwards from what SWC does. SWC runs capture analysis BEFORE props destructuring, so nested segments naturally capture `foo`, `bar` (the original names). OXC runs props destructuring first, so nested segments see `_rawProps.foo` and capture `_rawProps`.

The fix: In the child segment reclassification block (the `for seg in self.segments.iter_mut()` loop around line 3031):

1. First, check if the child segment captures `_rawProps` (or the `info.raw_props_name`).
2. If it does, REMOVE `_rawProps` from capture_names.
3. Then, look at the segment's body code (stored in `self.segment_body_codes`) to find which individual prop names from `local_aliases` are actually referenced via `_rawProps.propName` patterns.
4. Add those individual prop names to capture_names (in sorted/alphabetical order to match SWC).
5. Do NOT add _rawProps back.

Specifically, replace the block at lines ~3030-3049:
```rust
if let Some(parent_name) = component_segment_name {
    for seg in self.segments.iter_mut() {
        if seg.parent.as_ref() != Some(&parent_name) || seg.capture_names.is_empty() {
            continue;
        }
        // Remove _rawProps capture and replace with individual prop names
        let had_rawprops = seg.capture_names.contains(&info.raw_props_name);
        if had_rawprops {
            seg.capture_names.retain(|name| name != &info.raw_props_name);
            // Find which prop aliases are used in this segment's body
            // by checking segment_body_codes for _rawProps.propName patterns
            let body_code = self.segment_body_codes.iter()
                .find(|(span, _)| *span == seg.span.0)
                .map(|(_, code)| code.as_str())
                .unwrap_or("");
            for (original_key, local_alias) in &info.prop_keys {
                // Check if _rawProps.originalKey or the local alias appears in body code
                let prop_access = format!("{}.{}", info.raw_props_name, original_key);
                if body_code.contains(&prop_access) {
                    seg.capture_names.push(local_alias.clone());
                }
            }
            // Re-sort to maintain alphabetical ordering
            seg.capture_names.sort();
            seg.captures = !seg.capture_names.is_empty();
        }
    }
}
```

IMPORTANT: The `segment_body_codes` Vec<(u32, String)> stores (span_start, body_code) for segments. The body code string will contain references like `_rawProps.foo`, `_rawProps.bar` if the segment uses those props. Match against the ORIGINAL key name (the property key in the destructuring, not the local alias) because the body code uses `_rawProps.originalKey`.

Also handle the case where `info.prop_keys` has entries where original != local (aliased destructuring like `{foo: myFoo}`). In that case, look for `_rawProps.foo` but add `myFoo` to captures.

For segments that don't capture _rawProps at all (they only capture other variables), leave them unchanged.

Note: Also check if `example_lightweight_functional` test has a non-component$ arrow that needs the same treatment. Lightweight functionals (non-$-suffixed) detected as `export default` arrow functions may use a different rewrite path (Phase 12-06 added inline component _rawProps rewrite). Check if the same child reclassification logic applies there. If so, extend the reclassification to also run for inline components in exit_export_default_declaration.

   However, this is tricky because `compute_captures` doesn't have access to initializer info. A simpler approach: check if the captured name is in `const_bindings` (which tracks const declarations).
