Address the remaining 4 DCE tests:

**1. isBrowser/isServer in inline strategy (example_qwik_router_inline, example_qwik_react_inline):**

The `const_replace.rs` pre-pass uses `VisitMut` which recursively walks the entire AST, including into arrow function bodies and call expression arguments. So `isServer`/`isBrowser` identifiers SHOULD be replaced even inside $() callback arguments.

However, `example_qwik_react_inline` has pre-transformed code (`inlinedQrl(...)`) where the callback is already a string, not an AST node. The const_replace pass can't replace identifiers inside strings. This test may be fundamentally un-fixable with the current approach (deferred to "pre-transformed code" category in Phase 14).

For `example_qwik_router_inline`: Check if the issue is that:
a) The replacement IS happening but dead branch elimination doesn't propagate deep enough, OR
b) The body code serialization captures the pre-replacement source

If (b), the issue is that segment body code is serialized from source spans during traversal. The source code hasn't been modified by const_replace (it modifies the AST, not the source string). The body code serialization uses `codegen_expression_with_comments` which regenerates from the AST -- so the replacement should be visible.

Debug by examining the body code string for the qwik_router_inline segments to see if `isServer`/`isBrowser` references persist.

If the issue is in the entry module (Inline strategy keeps code in entry), check if `simplify_unused_pure_var_decls` in exit_program handles the dead branches. The DeadBranchEliminator already runs on the full program in const_replace.rs, so dead branches should be eliminated before exit_program.

If these tests are fundamentally about pre-transformed input that OXC can't handle, document as deferred.

**2. Intermediate const simplification (example_use_optimization, example_optimization_issue_4386):**

These tests have patterns like:
```js
const { val, set } = useSignal(0);
// SWC inlines: direct use of useSignal(0).val, useSignal(0).set
// OXC keeps: const { val, set } = useSignal(0); then uses val, set
```

This is a const-folding optimization that SWC's MinifyMode::Simplify performs. It's a complex transform that inlines destructured const references. Implementing this would require:
1. Detecting single-use destructured const patterns
2. Inlining the member access at each use site
3. Removing the const declaration

This is a significant transform. If the diff is small (just the destructuring line), it may be acceptable to defer to Phase 14 or accept as a minor semantic difference. Evaluate the actual diff size before implementing.

If the diff is just a few extra `const` lines that SWC removes, document as "minor DCE gap -- SWC inlines destructured const, OXC preserves" and move on.
